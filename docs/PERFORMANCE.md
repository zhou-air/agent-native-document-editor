# 架构重构性能复测（2026-10-14）

测试使用真实项目 `projects/项目-20261014-111032` 的临时副本：251 个章节、1,300 个旧格式顶层块；最大表格 278 行、2,949 个单元格。运行环境为 Windows、Node 24.19.0、Intel i5-12450H。原项目只读，测量写入均发生在临时目录。

## 同机旧版与新版对比

每个版本在独立 Node 进程打开同一份原始数据的副本，对同一个正文块实际提交五次，取中位数。旧版源码及其依赖已保存在 `artifacts/refactor-20261014/legacy-baseline/`，不会进入应用发布包。

| 指标                 |                                旧版 JSON Store |              新版 SQLite Store |
| -------------------- | ---------------------------------------------: | -----------------------------: |
| 单段真实提交，中位数 |                                   1,348.839 ms |                       2.857 ms |
| 单段写入响应，中位数 |                                36,884,622 字节 |                    10,216 字节 |
| 打开响应             |                                36,884,471 字节 |                    64,449 字节 |
| 重新打开             |                                   1,186.359 ms |                      17.554 ms |
| 活跃正文存储         | 104,079,247 字节（project.json + styles.json） | 3,113,016 字节（数据库及 WAL） |

本次单段提交约快 472 倍，响应体减少 99.972%，活跃正文存储减少约 97.0%。这组提交时间是 Store 层测量，**不包含 HTTP 传输、WinUI 控件渲染或用户输入延迟**，也不是跨机器承诺。独立运行的 HTTP 数据见下一节。

新版首次打开旧副本时包含自动迁移，耗时 546.668 ms。新项目需要为每个章节提供标题块；补充组织节点的标题不会改变原有正文块 ID。

测量时把新版 `snapshot()` 替换为直接抛错的方法，五次单段提交和 100 次空闲增量查询均未调用它。空闲增量查询合计 2.004 ms，文档版本不变。修改后原有 `project.json` 的大小与修改时间均未变化。SQLite 通过 WAL 写入必要页面；没有重写 JSON 或样式镜像。

这里比较的是正常编辑所需的活跃数据。迁移备份、保留的旧文件、原始 DOCX、图片、导出件和变更历史会继续占磁盘空间；不能把上述数字理解为包含全部备份的项目目录已经缩小 97%。

## 真实 HTTP 与大型表格

另一份完整真实项目副本通过带认证的本地 HTTP 服务完成以下操作。时间包含请求 JSON 生成、回环网络、服务事务和响应解析，仍不包含 WinUI 渲染：

| 操作                         |                         实测 |
| ---------------------------- | ---------------------------: |
| 单段提交，五次中位数         |                    18.625 ms |
| 最大表格所属章节读取         |                   109.740 ms |
| 最大表格单元格内容修改并提交 |                   161.523 ms |
| 撤销该表格修改               |                   125.385 ms |
| 100 次空闲增量请求           |   1,449.288 ms；文档版本不变 |
| 全项目 DOCX 导出             | 1,350.719 ms；3,488,828 字节 |

表格修改响应为 1,542,460 字节，只包含受影响的一个表格块及章节信息。表格内部未拆成独立顶层块，因此编辑单元格仍提交整个表格块；这是当前架构边界。撤销后逐节点比较与修改前一致，表格 ID 保留。导出的 DOCX 包含最后提交的正文修改；此处验证了 OOXML 内容，未据此声称 Microsoft Word 已实际打开。

## 同步与协议验证

`tests/service-v2.test.js` 的八项测试全部通过，涵盖真实 HTTP、两路 MCP 客户端、SSE 实时通知与断线补齐、同版本并发写入恰一成功、活动项目身份检查、按当前章节过滤增量正文与跨章节移出通知、DOCX/ZIP 导出、无 GUI 自动启动和旧项目副本迁移。机器日志在 `artifacts/refactor-20261014/service-tests-v2.txt`。

SSE 心跳不读取正文；兼容版本查询仅返回 ID 和 revision。当前章节按需读取，写操作返回受影响对象。客户端表格滚动、中文输入法及控件数量应以 WinUI 运行验证记录为准，不能由服务基准代替。

## 最终 WinUI 发布版实测

14:20 发布的实际 EXE 另完成合成 2,400 格 7/7、真实 2,949 格 8/8 项窗口测试。真实大章阅读时有 4 个文本编辑器，进入单元格编辑后为 5 个，重开后回到 4 个；并非创建 2,949 个 RichEditBox。普通段落提交时根内容比较计数保持 0→0，原目录元素保留。

真实项目本轮初启 2.513 秒，搜索选章及清除/恢复筛选 2.391 秒，合计 4.932 秒；重开初启 1.331 秒、同样导航操作 1.802 秒。这是单轮真实窗口结果，包含自动化调度、服务启动和交互，不能作为纯表格布局时间或与上文 Store 层中位数直接比较。

实际输入、单格保存、撤销/重做、首尾滚动、关闭重开和正文精确恢复均通过。原生“导出文档”按钮经 Windows 保存器输出 3,488,806 字节 DOCX。证据：`artifacts/refactor-20261014/native-final-ui/{synthetic,real}/native-ui-results.json`，详细操作边界见 [WinUI 说明](WINUI.md)。

## 复测方法与证据

```powershell
node --expose-gc scripts/benchmark-v2.mjs
node scripts/benchmark-service-v2.mjs
node --test tests/service-v2.test.js
```

`benchmark-v2.mjs` 支持 `--project <旧项目目录>`、`--output <JSON路径>`、`--baseline <重构前源码ZIP>`，以及只复测新版的 `--skip-legacy`。脚本保留临时副本，便于检查数据库、迁移报告和导出结果。旧版基准依赖其隔离归档，不能使用清理后的应用依赖来重跑旧版。

- `artifacts/refactor-20261014/performance-v2.json`：逐次 Store 提交数据、数据库/WAL 大小、内存、重新打开及身份验证。
- `artifacts/refactor-20261014/performance-service-v2.json`：完整 HTTP 流程、大表格保存/撤销、空闲查询及 DOCX 导出。
- `artifacts/audit-20261014/audit-results.json`：重构前审计原始记录。此前单段约 2.58 秒是另一轮测量；本报告使用同机重跑的 1.35 秒中位数作比较，未混用两轮数据。

变更日志保存受影响块的必要前后状态以支持撤销和重放。反复编辑大型表格会增长历史数据；后续可增加经过确认的历史保留策略和归档，当前不会为压缩体积而自动删除撤销依据。
