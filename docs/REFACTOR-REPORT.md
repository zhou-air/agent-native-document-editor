## 已实现的行为

Block 使用永久 ID 保存内容、类型及修订号；复制分配新 ID，修改、移动、保存、重开保留 ID。Section 使用独立 ID 与标题块，名称直接来自标题内容；父子关系决定标题层级。章节与块共享确定性排列规则，支持父节正文位于子节之后。

SQLite 是唯一正文权威数据，使用 WAL、事务、版本检查与墓碑版本。正常编辑只写受影响块、必要章节版本与变更记录；文档没有第二份完整正文，旧 JSON 和样式镜像不再更新。新增 Repository 边界集中管理数据库生命周期、事务和语句；当前部分业务操作仍使用 SQL，替换为非 SQL 存储还需适配这些操作。

WinUI 按需加载当前章节，保存脏块并增量更新内容与目录。撤销、重做、草稿记录块级变化。大型表格以轻量文字展示，只有活动单元格创建富文本编辑器。输入遇到同块外部修改时保留草稿并报告冲突，不直接覆盖用户输入。服务提供 SSE 和按 revision 补齐接口；WinUI 使用轻量版本检查与带游标增量读取。

MCP 提供 Block/Section 的读取、创建、修改、移动、复制、删除，批量章节读取、变更查询、撤销和 DOCX 导出。服务端创建 ID，写入检查版本，默认返回局部结果。旧章节工具保留兼容入口。两路 Agent 与桌面共用服务和版本规则。

DOCX 导入提取标题、正文、表格合并、图片及行内语义，复杂内容生成提示并保留归档原件。导出生成真实可编辑 DOCX，独立模板集中控制排版。内容控件与轻量自定义数据保存身份和组织关系，正文仅以 Word 实际内容为准；在 Word 中改变章节或块顺序后重新导入，会尊重新顺序。

## 迁移结果

真实项目原有 251 节、1,300 块，包含 59 个表格、9 处图片引用，最大表格为 278 行、2,949 个单元格。迁移副本保留全部 1,300 个原 Block ID，未发生 ID 重映射；为没有标题块的“前言”组织节点补充一个标题块，因此新版共有 1,301 块。

迁移先自动备份，再构建临时数据库，验证逐块语义内容、表格结构、图片引用、章节组织顺序及数据库完整性，成功后才启用。失败测试证明原文件和备份可保留，未激活不完整数据库。真实项目证据为 `artifacts/refactor-20261014/large-project-v2/migration-report.json`；其 `backups/` 保留旧项目文件。

迁移只能保护旧项目中已经保存的内容，不能补回旧导入器曾经遗漏的信息。源字体、字号、行距、XML 与局部样式镜像按本次要求不进入新正文模型。

## 性能前后对比

同一台 i5-12450H 电脑，对同一真实项目副本和同一正文块分别实际提交五次，取中位数：

| 指标 | 旧版 | 新版 |
| --- | ---: | ---: |
| Store 层单段提交 | 1,348.839 ms | 2.857 ms |
| 单段提交响应 | 36,884,622 字节 | 10,216 字节 |
| 打开项目响应 | 36,884,471 字节 | 64,449 字节 |
| 重开项目 | 1,186.359 ms | 17.554 ms |
| 活跃正文存储 | 104,079,247 字节 | 3,113,016 字节 |

单段提交约快 472 倍，活跃正文存储减少约 97%。这里不包含界面渲染，也不包含旧数据备份、图片、原件和历史累积占用，不能解释为整个项目文件夹缩小了 97%。

真实 HTTP 路径单段提交中位数为 18.625 ms，最大表格单元格修改并提交为 161.523 ms，撤销为 125.385 ms，完整 DOCX 导出为 1,350.719 ms。将全量 `snapshot()` 替换成抛错函数后，单段保存和空闲增量查询仍正常完成；没有把全文序列化当作变化检测。详细数据、测量边界与复测命令见 [性能说明](PERFORMANCE.md)。

## 已知限制与扩展方向

- Microsoft Word 实机验收仍需在安装了该软件的环境补做；已确认的实际打开/另存结果来自 WPS。没有执行人工逐页排版检查。
- 大表消除了成千个 RichEditBox，但轻量单元格仍需整体布局，尚未实现行虚拟化。单元格编辑提交整个 Table Block，本次最大表格的局部响应约 1.54 MB。
- 中文输入法的组合状态保护已保留；自动 Unicode 输入和中文粘贴不能代表所有真实输入法的人工验收。
- 公式、复杂域、批注、修订、浮动图形等有转换提示和归档来源，不承诺完整原生编辑。WMF/EMF 等图片可保留并导出，编辑区显示取决于系统支持。
- Word 中删除身份内容控件或剥除自定义数据后，无法仅凭相同文字恢复原 ID。自动章节编号仅预留，不额外重复添加标题编号。
- 修改记录保留受影响块的必要前后状态，重复编辑大型表格会增加历史体积；尚未自动清理历史。导出模板修改有版本记录，但尚未接入内容撤销。
- Repository 已隔离持久化入口，当前并非可直接换用任意非 SQL 引擎。更细表格增量、行虚拟化、历史归档、完整 IME/Word 环境验收是后续可扩展方向。
