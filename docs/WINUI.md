# 原生 WinUI 3 文档工作台（v2）

双击仓库根目录 `启动文档工作台.cmd`，或运行完整发布目录内的 `AgentDocument.WinUI.exe`。发布程序包含 .NET、Windows App SDK 和独立 Node.js 后台；移动程序时保留整个目录。桌面界面仅使用 WinUI 3 原生控件。

## 日常编辑

默认启动显示应用内最近项目首页，提供新建、导入 Word、浏览已有项目及刷新入口。导入 DOCX 后直接在应用 projects 目录建立独立项目，名称取文件名；重复导入分开保存。点击“打开”或“项目首页”返回列表，正文先保存；未提交样式在切换项目时仍需明确处理。显式 `--project` 保留直接打开行为。

2026-10-14 本次改造验证：后台测试 55 项通过，原生客户端 13 项通过，编辑模型 21 项通过；项目首页与样式的原生操作验证 7 组通过，原有大表格编辑、撤销、滚动和重新打开验证通过。新界面操作记录为 `artifacts/home-styles/home-styles-results.json`，原有功能回归记录为 `artifacts/winui/winui-results.json`。

- 左侧选择章节，按需载入该章节直属内容块。标题、正文、表格、图片均使用稳定 Block ID；章节使用独立 Section ID。
- 正文停止输入 500 毫秒后自动保存，Ctrl+S 立即保存。修改普通段落仅发送该块与版本，不传整章或整个项目。
- Enter 分段，段首 Backspace 合并；Ctrl+B / Ctrl+I / Ctrl+U 设置行内语义。功能区支持粗体、斜体、上下标、下划线和删除线。
- “内容块”中的“复制”将所选块放入系统剪贴板，不会在原地新增。可在右侧“本节内容”列表用 Ctrl 点击多选或 Shift 点击选连续块，再切换到目标位置，点击“粘贴”，插入到当前选中块后；没有选中块时追加到本节末尾。粘贴内容创建新 ID；移动保留 ID。章节标题不能作为普通块删除或移出，请在“开始 → 章节组织”重命名、调整同级顺序、换父章节或删除章节及其子章节。
- 表格可以增删行列、合并及拆分。超过 100 个单元格时默认显示轻量文字，点击单元格后才创建原生富文本编辑器；Tab / Shift+Tab 切换活动单元格。小表仍直接编辑全部单元格。
- Ctrl+A 选择本节内容块；Shift 点击选择连续块。有文字选中时 Ctrl+C 复制文字，整块复制使用“复制”按钮或内容块多选。粘贴普通文字时，已有内容的块按当前光标插入或替换选中文字，多段文字仍保留在同一块；空白正文块接收第一段，后续非空段落生成新块，空行跳过。完整块的拷贝仍插入到目标块后，保留正文、表格和图片结构；没有选中块时追加到本节末尾。Ctrl+V 和“粘贴”按钮使用相同规则。章节标题身份受到保护。

正文和标题 1～9 的统一样式移至顶部“布局与样式”，提供中文和西文字体、字号、加粗、对齐、三种行距（单倍、1.5 倍、2 倍）、段前段后距及首行缩进（磅）。点击“应用样式”保存后，编辑区与 Word 导出共用项目级 styles。局部强调保留，样式继承的加粗不会因输入文字被写成局部标记；格式刷新保留正文历史和选择。页面、预设和详细模板也在顶部进入。旧项目其他行距不因读取或修改字体而改写。编辑区不模拟 Word 分页。

项目列表接口 `GET /api/projects?root=项目目录` 合并直属项目目录、运行目录中的 recent-projects.json 及 last.json。摘要包含 title、path、updatedAt、lastOpenedAt、available 和错误说明；路径规范化去重。SQLite 使用只读摘要查询，旧 project.json 只读取，不迁移、不切换活动 Store。

## 保存、同步与恢复

本地 Node.js 文档服务是唯一写入者，SQLite 事务负责提交与版本检查。客户端只持有轻量目录和当前章；空闲轮询只读取版本号。检测到变更后按当前 Section ID 获取增量，不下载其他章节的正文。标题变更更新既有导航节点。

普通撤销/重做记录受影响块的前后内容，结构操作额外记录块 ID 顺序；不保存整章历史副本。已提交删除的撤销使用服务端墓碑版本恢复原 Block ID，版本过期时拒绝恢复。跨章节移动使用逆向移动操作及块版本检查。

未提交草稿只包含改变的块、基准版本及必要的结构顺序。不同块的并发修改会合并；同块修改、外部删除或移走正在编辑的块时保留本地输入并提示冲突。重新打开发现草稿时要求明确选择已保存版本，避免自动覆盖更新内容。SSE 已由服务提供；WinUI 当前使用等效的轻量版本检查和带游标增量拉取。

## 导入和导出

“导入 Word”读取 DOCX 核心正文、标题、表格结构、图片及行内语义，保留归档原件和转换提示。打开旧 `project.json` 项目时由服务自动备份、迁移、验证后启用 `document.sqlite`。

“导出文档”默认输出可编辑 `.docx`；也可以选择结构化 `.zip` 内容包。可导出完整文档或当前章节。Word 排版由独立导出模板控制；来源 XML、局部字体镜像及样式继承链不参与日常编辑。

## 开发与验证

```powershell
npm ci
./scripts/publish-winui.ps1
dotnet run --project native/AgentDocument.ClientChecks -c Release -- .
dotnet run --project native/AgentDocument.EditorChecks -c Release
./scripts/check-winui.ps1
```

`native/AgentDocument.Client` 实现轻量清单、按需章节、块级提交、增量刷新和草稿；`native/AgentDocument.WinUI/Controls` 实现原生编辑、块级历史及表格逻辑矩阵。导出接口为 `POST /api/export`，`format: docx | zip`。完整接口见项目 MCP 和数据格式说明。

实际客户端测试覆盖单块负载、并发合并、冲突保留、保存途中输入、删除恢复同 ID、后台章不传正文、空闲版本检查及草稿恢复。原生 UI 自动化见 `tests/winui/incremental-v2.ps1`，通过真实窗口输入、保存、撤销重做、活动单元格、滚动和重开验证，不将模型检查当作界面验证。

## 当前限制

- 大表已消除一次创建全部 RichEditBox 的开销，但轻量单元格仍整体布局，尚未实现行虚拟化；很长章节仍需要布局时间。
- 表格作为单个 Block 提交，因此编辑一个单元格会写入该表格块。撤销也会保留受影响表格自身的数据。
- 不实现 Word 精确分页、跨段任意文字拖选、复杂域或公式的完整编辑；转换提示和归档原件保留供核对。
- 中文输入法组合状态的保护逻辑保留。自动化 Unicode 键盘输入及中文粘贴不等价于所有实际输入法的人工验证。
- 功能测试与原生构建结果独立记录；本次未执行人工逐页视觉验收。
