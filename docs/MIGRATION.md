# 旧项目迁移与回滚

推荐使用副本验证，原项目无需手工删除字段：

```powershell
node scripts/migrate-project.mjs "旧项目目录" "全新的目标目录"
```

也可在 WinUI 中直接打开旧项目目录；程序执行相同迁移流程。

1. 取得该项目文件锁，复制 `project.json`、`styles.json`、`assets/` 和 `original/` 到 `backups/v1-时间-随机码/`。
2. 读取旧模型，保留所有不冲突的 Section/Block ID。缺失或重复 ID 记录重映射。
3. 以语义节点建立临时 SQLite，保留正文、行内语义、表格合并、图片引用与层级。没有标题块的前言等章节新增对应 Heading，记录在 `syntheticHeadings`，不删除原正文。
4. 核对每个块的语义读回、身份、归属、图片存在性、数据库关系和章节遍历顺序。旧平铺顺序若与父子层级冲突，停止迁移，不自行改变正文顺序。
5. 成功才启用 `document.sqlite` 并写 `migration-report.json`。原来的两个 JSON 不再参与编辑，也不被重写。

失败时旧文件和备份保留，临时数据库不会成为当前项目。修复报告所列问题后可以重试。不要删除原文件来强行跳过验证。

## 回滚

关闭项目和本程序的后台服务后，从 `backups/v1-...` 复制出一个新的文件夹，再用旧版本程序打开。旧版源码档案位于本次 `artifacts/refactor-20261014`；本次发布使用 `-KeepPrevious` 保留旧程序在 `release/.previous-winui-*`。今后自行发布也需显式加该参数才保留上一版程序。新程序再次打开旧副本会重新迁移。

回滚到迁移前状态不会包含之后的编辑。需要保留后续工作时，先用新程序导出 DOCX/内容包，并保存整个新项目。不要在正在运行的数据库上移动或只复制主 SQLite 文件。

## 范围与体积

迁移保证旧项目**已保存的语义内容**，不能恢复旧导入器从未保存的内容。真实原件存在复杂对象和上下标等旧版处理边界；若需重新提取，应使用新版重新导入原 DOCX，再对照导入告警检查。

来源字体、页式、原 XML、复杂样式继承和局部覆盖已明确放弃。保留独立导出模板，不保留正文样式镜像。

性能报告中的“新数据库体积”不包含自动备份、旧 JSON、原始 DOCX 和图片。为了保护历史，迁移后整个目录可能更大；旧数据和备份的归档/清理由用户决定，本次不自动清理。

已完成的真实副本：`artifacts/refactor-20261014/large-project-v2`。报告中原块 1,300 个全部保持身份，另为前言新增一个 Heading，因此新库有 1,301 个块。
